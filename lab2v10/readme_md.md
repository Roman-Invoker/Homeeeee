# Лабораторна робота №2: Клас із кількома конструкторами. Життєвий цикл об’єкта

**Предмет:** Об’єктно-орієнтоване програмування (C# / .NET)

**Варіант:** №2 (`Клас Car`)

**Тривалість:** 2 год

**Інструменти:** .NET SDK, Visual Studio / JetBrains Rider / VS Code

## 🎯 Мета роботи

Навчитися реалізовувати перевантажені конструктори, дослідити порядок їх викликів, опанувати ланцюговий виклик через `: this()` та зрозуміти основи життєвого циклу об’єкта (включаючи роботу збирача сміття GC та деструкторів) у мові C#.

## 📚 Теоретичні відомості

* **Перевантаження конструкторів (Constructor Overloading):** Створення в одному класі кількох конструкторів із різним набором чи типами параметрів для гнучкого створення об'єктів.

* **Ланцюговий виклик (`: this(...)`):** Конструктор може викликати інший конструктор того ж класу, що дозволяє уникнути дублювання коду ініціалізації (DRY - *Don't Repeat Yourself*).

* **Життєвий цикл об’єкта:**

  1. **Створення:** Оператор `new` виділяє пам’ять у купі (heap) та викликає відповідний конструктор.

  2. **Використання:** Об’єкт живе й виконує задачі, доки на нього існує хоча б одне посилання.

  3. **Знищення:** Збирач сміття (*Garbage Collector / GC*) автоматично звільняє пам'ять, коли на об'єкт немає посилань.

* **Деструктор (Фіналізатор):** Метод з ім'ям `~ClassName()`, який викликається збирачем сміття перед видаленням об’єкта.

## 📋 Завдання за варіантом №2

### Клас `Car`

* **Приватні поля:** `_brand` (`string`), `_model` (`string`), `_year` (`int`).

* **Публічні властивості:**

  * `Brand`

  * `Model`

  * `Year` — **з валідацією** (рік не може бути в майбутньому).

* **Конструктори:**

  * За замовчуванням: `Brand = "Unknown"`, `Model = "Unknown"`, `Year = 2000` (реалізовано через ланцюговий виклик `: this(...)`).

  * Параметризований: `(string brand, string model, int year)`.

* **Метод:** `StartEngine()` — виводить повідомлення про запуск двигуна.

* **Деструктор:** `~Car()` — виводить повідомлення про знищення об’єкта збирачем сміття.

### 2. Реалізація класу та програми (`Program.cs`)

```
using System;

namespace Lab2v2
{
    /// <summary>
    /// Клас, що описує автомобіль (Варіант 2)
    /// </summary>
    public class Car
    {
        // Приватні поля
        private string _brand;
        private string _model;
        private int _year;

        // Властивість Brand
        public string Brand
        {
            get => _brand;
            set => _brand = string.IsNullOrWhiteSpace(value) ? "Unknown" : value;
        }

        // Властивість Model
        public string Model
        {
            get => _model;
            set => _model = string.IsNullOrWhiteSpace(value) ? "Unknown" : value;
        }

        // Властивість Year з валідацією (рік не може бути в майбутньому)
        public int Year
        {
            get => _year;
            set
            {
                int currentYear = DateTime.Now.Year;
                if (value > currentYear)
                {
                    Console.WriteLine($"[Валідація] Помилка: Рік ({value}) не може бути більшим за поточний ({currentYear}). Встановлено 2000.");
                    _year = 2000;
                }
                else
                {
                    _year = value;
                }
            }
        }

        // Конструктор за замовчуванням, який викликає параметризований через : this()
        public Car() : this("Unknown", "Unknown", 2000)
        {
            Console.WriteLine("--> Викликано конструктор за замовчуванням (через : this(...))");
        }

        // Параметризований конструктор
        public Car(string brand, string model, int year)
        {
            Console.WriteLine("--> Викликано параметризований конструктор");
            Brand = brand;
            Model = model;
            Year = year;
        }

        // Метод для запуску двигуна
        public void StartEngine()
        {
            Console.WriteLine($"[Car] Двигун автомобіля {Brand} {Model} ({Year} р.) заведено! Врум-врум!");
        }

        // Деструктор (Фіналізатор)
        ~Car()
        {
            Console.WriteLine($"[~Car] Збирач сміття (GC) знищив об'єкт: {Brand} {Model} ({Year})");
        }
    }

    internal class Program
    {
        private static void Main(string[] args)
        {
            Console.WriteLine("=== Створення об'єктів ===");

            // 1. Об'єкт за допомогою конструктора за замовчуванням
            Car car1 = new Car();
            car1.StartEngine();

            Console.WriteLine();

            // 2. Об'єкт за допомогою параметризованого конструктора
            Car car2 = new Car("Toyota", "Camry", 2021);
            car2.StartEngine();

            Console.WriteLine();

            // 3. Об'єкт з некоректним роком (презентація валідації)
            Car car3 = new Car("Tesla", "Cybertruck", 2099);
            car3.StartEngine();

            Console.WriteLine("\n=== Об'єкти створено ===");
            Console.WriteLine("Завершення роботи Main, підготовка до виклику GC...");

            // Примусовий запуск GC (лише для навчальних цілей!)
            GC.Collect();
            GC.WaitForPendingFinalizers();

            Console.WriteLine("Програму завершено.");
        }
    }
}

```

## ❓ Контрольні запитання

1. **Що таке перевантаження конструкторів і яку перевагу воно дає?**

   * *Відповідь:* Це оголошення кількох конструкторів у межах одного класу з різними параметрами. Це надає гнучкість при створенні об'єктів (можна ініціалізувати об'єкт як з усіма даними, так і зі значеннями за замовчуванням).

2. **Як за допомогою `: this()` можна уникнути дублювання коду ініціалізації?**

   * *Відповідь:* Один конструктор може перенаправляти виклик до іншого конструктора того ж класу, передаючи йому базові значення. Завдяки цьому логіка валідації чи присвоєння полів знаходиться в одному місці.

3. **Хто і в який момент викликає деструктор (фіналізатор) у C#?**

   * *Відповідь:* Деструктор викликається автоматично збирачем сміття (Garbage Collector), коли об'єкт стає недосяжним (на нього немає посилань у програмі) і GC вирішує очистити пам'ять.

4. **Чому в реальних програмах не рекомендується викликати `GC.Collect()` вручну?**

   * *Відповідь:* Спроба примусового запуску GC блокує потоки, сповільнює роботу програми та порушує оптимізований алгоритм роботи середовища CLR, яке самостійно визначає найефективніший момент для збору сміття.

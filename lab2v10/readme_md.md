# Лабораторна робота №2: Клас із кількома конструкторами. Життєвий цикл об’єкта

**Предмет:** Об’єктно-орієнтоване програмування (C# / .NET)  
**Варіант:** №14 (`Клас Restaurant`)  
**Тривалість:** 2 год  
**Інструменти:** .NET SDK, Visual Studio / JetBrains Rider / VS Code

##  Мета роботи

Навчитися реалізовувати перевантажені конструктори, дослідити порядок їх викликів, опанувати ланцюговий виклик через `: this()` та зрозуміти основи життєвого циклу об’єкта (включаючи роботу збирача сміття GC та деструкторів) у мові C#.

---

##  Теоретичні відомості

* **Перевантаження конструкторів (Constructor Overloading):** Створення в одному класі кількох конструкторів із різним набором чи типами параметрів для гнучкого створення об'єктів.
* **Ланцюговий виклик (`: this(...)`):** Конструктор може викликати інший конструктор того ж класу, що дозволяє уникнути дублювання коду ініціалізації (принцип DRY - *Don't Repeat Yourself*).
* **Життєвий цикл об’єкта:**
  1. **Створення:** Оператор `new` виділяє пам’ять у купі (heap) та викликає відповідний конструктор.
  2. **Використання:** Об’єкт живе й виконує задачі, доки на нього існує хоча б одне посилання.
  3. **Знищення:** Збирач сміття (*Garbage Collector / GC*) автоматично звільняє пам'ять, коли на об'єкт немає посилань.
* **Деструктор (Фіналізатор):** Метод з ім'ям `~ClassName()`, який викликається збирачем сміття перед видаленням об’єкта з пам'яті.

##  Завдання за варіантом №14

### Клас `Restaurant`

* **Приватні поля:** `_name` (`string`), `_cuisine` (`string`), `_rating` (`double`).
* **Публічні властивості:**
  * `Name`
  * `Cuisine`
  * `Rating` — **з валідацією** (рейтинг має бути від 1.0 до 5.0).
* **Конструктори:**
  * **За замовчуванням:** `Name = "Unnamed"`, `Cuisine = "Mixed"`, `Rating = 3.0` (реалізовано через ланцюговий виклик `: this(...)`).
  * **Параметризований:** `(string name, string cuisine, double rating)`.
* **Метод:** `ServeDish(string dishName)` — виводить повідомлення про подачу страви.
* **Деструктор:** `~Restaurant()` — виводить повідомлення про знищення об’єкта збирачем сміття.

### 2. Реалізація класу та програми (`Program.cs`)

```csharp
using System;

namespace OOPLab2
{
    public class Restaurant
    {
        
        private string _name;
        private string _cuisine;
        private double _rating;

      
        public string Name
        {
            get => _name;
            set => _name = string.IsNullOrWhiteSpace(value) ? "Unnamed" : value;
        }

        public string Cuisine
        {
            get => _cuisine;
            set => _cuisine = string.IsNullOrWhiteSpace(value) ? "Mixed" : value;
        }

        public double Rating
        {
            get => _rating;
            set
            {
                if (value < 1 || value > 5)
                    throw new ArgumentOutOfRangeException(nameof(value), "Рейтинг повинен бути в межах від 1 до 5.");
                _rating = value;
            }
        }

        
        public Restaurant() : this("Unnamed", "Mixed", 3.0)
        {
        }

    
        public Restaurant(string name, string cuisine, double rating)
        {
            Name = name;
            Cuisine = cuisine;
            Rating = rating;
            Console.WriteLine($"[Конструктор] Створено ресторан \"{Name}\".");
        }

       
        public void ServeDish(string dishName)
        {
            Console.WriteLine($"Ресторан \"{Name}\" ({_cuisine} кухня) подає страву: {dishName}. " +
                               $"Рейтинг закладу: {Rating:F1}");
        }

      
        ~Restaurant()
        {
            Console.WriteLine($"[Деструктор] Об'єкт Restaurant \"{_name}\" знищується збирачем сміття.");
        }
    }

    class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("=== Creating objects ===");

            Restaurant r1 = new Restaurant(); 
            Restaurant r2 = new Restaurant("La Pasta", "Italian", 4.7);
            Restaurant r3 = new Restaurant("Sushi Time", "Japanese", 4.9);

            Console.WriteLine("\n=== Objects created ===\n");

            r1.ServeDish("House Salad");
            r2.ServeDish("Spaghetti Carbonara");
            r3.ServeDish("Salmon Nigiri");

          
            try
            {
                r1.Rating = 10; 
            }
            catch (ArgumentOutOfRangeException ex)
            {
                Console.WriteLine($"\n[Валідація] Помилка: {ex.Message}");
            }

            Console.WriteLine("\n=== End of Main, preparing for GC ===");

            r1 = null;
            r2 = null;
            r3 = null;

            GC.Collect();
            GC.WaitForPendingFinalizers();

            Console.WriteLine("=== Program finished ===");
        }
    }
}
```

##  Контрольні запитання

1. **Що таке перевантаження конструкторів і яку перевагу воно дає?**
   * *Відповідь:* Це створення кількох конструкторів у межах одного класу з різним набором чи типами параметрів. Це дає гнучкість, дозволяючи створювати об'єкти різними способами (наприклад, з даними за замовчуванням або з власними значеннями).

2. **Як за допомогою `: this()` можна уникнути дублювання коду ініціалізації?**
   * *Відповідь:* Ключове слово `: this()` дозволяє одному конструктору викликати інший конструктор того ж класу. Завдяки цьому вся основна логіка ініціалізації та валідації знаходиться в одному місці (головному конструкторі), а інші лише передають значення.

3. **Хто і в який момент викликає деструктор (фіналізатор) у C#?**
   * *Відповідь:* Деструктор викликається автоматично збирачем сміття (*Garbage Collector*), коли об'єкт стає недосяжним (на нього більше немає посилань в програмі) і GC звільняє виділену під нього пам'ять.

4. **Чому в реальних програмах не рекомендується викликати `GC.Collect()` вручну?**
   * *Відповідь:* Примусовий виклик GC призупиняє виконання потоків програми, призводить до перевитрати ресурсів та порушує оптимізовані внутрішні алгоритми CLR, яке самостійно визначає найефективніший момент для збирання сміття.
